# Разовый анонс TopPsyGame

Одно сообщение по существующей базе cardbot: текст, картинка и две ссылки
с UTM-метками. Без продолжений, без D+2 и D+5 — анонс и всё.

Это **не** воронка из `README_platform_campaign.md`. Разница в том, кто
начинает разговор: воронку человек открывает сам, анонс приходит без спроса.
Поэтому анонс — рекламная рассылка по смыслу ст. 18 № 38-ФЗ, и уйти он может
только тем, чьё согласие такие сообщения покрывает.

## Из чего состоит

| Файл | Что в нём |
|---|---|
| `modules/texts/announcement.py` | согласованный текст, обе ссылки, сборка UTM |
| `modules/post_management.py` | отправка поста, лимиты длины (изменён) |
| `main.py` | команды `/create_announcement`, `/post_media`, `/preview_post` |
| `assets/announcement_spread.jpg` | картинка анонса (расклад на игровом столе) |
| `assets/announcement_table.jpg` | она же, вариант с полным интерфейсом комнаты |
| `tools/preview_announcement.py` | предпросмотр без деплоя, только админам |
| `tests/test_announcement_post.py` | регрессионные проверки |

Механизм рассылки переиспользован целиком: посты, рассылки, сегменты и отсев
заблокировавших — те же, что были. Добавлены только картинка к посту и
предпросмотр.

## Порядок действий

1. Прислать боту картинку.
2. Ответом на неё — `/create_announcement`. Пост соберётся сам: текст и ссылки
   с метками берутся из `modules/texts/announcement.py`, руками ничего набирать
   не нужно. В ответе будет ID поста.
3. `/preview_post ID` — пост придёт **только вам**, ровно в том виде, в каком
   его увидят получатели. Рассылка при этом не создаётся, в статистику проверка
   не попадает.
4. Открыть обе ссылки из предпросмотра и убедиться, что `utm_*` доехали целиком.
5. Только после этого — `/send_post ID СЕГМЕНТ`.

До деплоя шаги 1–4 заменяет `python tools/preview_announcement.py`: тот же
текст, та же картинка, тот же бот, получатель — только `ADMIN_ID`.

## Ссылки и метки

```
лендинг:    https://toppsygame.ru/?utm_source=cardbot&utm_medium=telegram
            &utm_campaign=platform_announcement&utm_content=site#platform
приложение: https://online.toppsygame.ru/?utm_source=cardbot&utm_medium=telegram
            &utm_campaign=platform_announcement&utm_content=app
```

* Якорь стоит **после** query-строки. `/#platform?utm_source=...` означало бы,
  что параметры стали частью фрагмента, и до аналитики они бы не доехали — молча.
* Кампания отдельная (`platform_announcement`, а не `platform_launch`): главный
  вопрос по анонсу — сколько людей после него дошло до регистрации, и это должно
  отделяться от воронки одним фильтром, а не вычитанием меток.
* В ссылках нет Telegram ID и других персональных данных: список допустимых
  `utm_content` закрыт, остальное отклоняется с `ValueError`.
* В сообщении ссылки оформлены как HTML-анкоры, поэтому видимый текст совпадает
  с согласованным (`toppsygame.ru/#platform`), а метки не торчат простынёй.

## Чего здесь нет

* **Проверки согласий.** В базе нет признака «согласен на рекламные сообщения»:
  сегменты `core`/`fresh`/`asleep`/`oneshot` описывают активность, а не согласие.
  Отбор аудитории — решение человека, и код его не подменяет.
* **Автоматической отправки.** Никакой планировщик анонс не запускает: пост
  создаётся командой, отправляется командой.
* **Конверсий в отчёте бота.** Клик по ссылке и регистрацию на платформе бот не
  видит. Это меряется на стороне TopPsyGame по UTM-меткам.

## Лимит подписи

С картинкой текст уходит подписью к фото, а подпись вмещает **1024** символа
вместо 4096. Раньше это было неважно — медиа к постам не прикреплялось, — и
валидация пропускала любой текст до 4096. Теперь длина проверяется с учётом
картинки, и при создании, а не в середине рассылки. Проверка идёт по сырому
содержимому вместе с HTML-разметкой, хотя Telegram меряет уже разобранный
текст: запас в нашу сторону лучше, чем падение на отправке.

Текущий анонс: 660 символов разметки, 389 видимых — запас больше чем вдвое.

## Картинка

`media_file_id` — это `file_id` Telegram, а не файл в базе. Картинка
загружается один раз, при создании поста, и дальше переиспользуется для всех
получателей. Файлы в `assets/` нужны, чтобы было что прислать боту и чтобы
отправленное можно было воспроизвести.
